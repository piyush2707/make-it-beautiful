# Contributing

Thanks for taking an interest in Make It Beautiful. Useful contributions make the skill work better in real projects, not just longer.

## Before opening a pull request

- Explain the problem or use case.
- Keep guidance practical and framework-agnostic where possible.
- Prefer small, reviewable changes.
- For a change to the skill, include an example of the situation it improves.
- Don't claim browser, accessibility, or test verification unless it was actually performed.

## Good contributions

- clearer design guidance
- framework-agnostic improvements
- useful prompts and grounded before/after examples
- accessibility and responsive-design improvements
- corrections to setup instructions

## Pull request checklist

- [ ] The change has a clear reason.
- [ ] Existing behavior and project conventions are respected.
- [ ] Documentation matches actual behavior.
- [ ] Any checks mentioned were actually run.

Please keep reviews kind and constructive. Design is contextual; explain the trade-offs behind your suggestions.
